# 从输出判断，到按秒返修

## 先选能暴露问题的时间

尽早输出最能代表本片视觉方向的镜头/短段。为每种主体动作或运镜选起点、经过、到达与结果帧；给最密集文字、最大数值、边缘位置、空间接触单独一帧。每个切点看前后有序帧；复杂镜头再渲染短片段。不是按固定间隔截图越多越好。

使用渲染脚本，例如在工程目录：

```text
npm run typecheck
npm run still -- --frame 45 --out out/check-45.png
npm run clip -- --range 2.6:3.5 --out out/cut-v1.mp4
npm run render -- --out out/film-v1.mp4
```

实际用宿主 `read_image` 或等价工具打开 PNG。只调用渲染命令不算检查画面。若工具只能返回图像链接而模型没有实际获得像素，记录能力缺口；修图像路由，不能用模型对自己代码的描述代替视觉检查。

## 看什么、怎样判定

| 观察 | 通过的依据 | 发现问题后 |
| --- | --- | --- |
| 事实与读数 | 数值、单位、轴、旁注与结论一致，产品能力有依据或标明概念 | 改统一数据源与转换，不只改一处标签 |
| 中文和主体 | 实际尺寸下可读，无方框、裁切、遮挡；重要信息层级清楚 | 改字量、字号、位置或构图，再看极端状态 |
| 动作因果 | 观众看得见谁先做什么、谁响应、结果如何改变 | 调路径、时序、停顿和反应，别只加模糊 |
| 时序与转场 | 关键动作完成、有结果停留；切换没有两组内容抢读 | 调镜头时长或局部进度，检查相邻镜头 |
| 整体表达 | 有展开与收束，画面语言兑现本片方向/参考；字幕之外还有可见过程和情绪 | 先改缺失的主体动作、构图或空间，不只给标题换色 |
| 镜头与尺度 | 景别、运动与切换有动机，层级/尺度锚点清楚；重要画面缩小后仍有主次 | 调机位、距离、前中后景或图形层级 |
| 光与材质 | 实体世界的方向光、受光/暗面、遮挡和接触成立；图形世界亮度/虚实有选择 | 先改主体、光和材质，再加辉光/颗粒 |
| 文字与风格 | 字幕或主文字在适当时刻引导视线；没有无意的常驻界面外壳，代表帧符合约定风格 | 调观看关系与字量，不把装饰数量当电影感 |
| 声音 | 音轨存在、完整播放适合内容，重点清楚、首尾自然 | 定位音源、包络、混音或同步问题后改 |

这些检查按片子的表达任务使用，不要求每帧都缩略截图或一律物理打光；有意黑场、运动模糊和界面演示也需结合上下文判断。代表性画面仍像用户已否决的演示稿/绘本时，先修视觉系统，不能凭知识正确和能导出就通过。

连续动态、完整播放和实际听音需要分别完成。代表帧只证明对应瞬间；有序帧只证明采样区间的变化。FFprobe 检查不能证明美感和知识正确，FFmpeg 静音检测不能证明好听。

## 交给人工与收回意见

完整导出后，给出可打开的 MP4 与“秒数/区域—看到或听到的问题—应保留内容”的反馈方式。宿主有审片工具时使用它的独立任务，不把他人的在审影片切走；公开用户无需安装作者的私人工具。无法感知的声音和连续播放范围明确交给人工，未答复保持待验收。

意见与实际文件版本绑定。必要时核对时长、尺寸与文件身份，防止把旧片时间码套进新版。返修流程：读原意见与保留项 → 定位到镜头和局部帧 → 修改最小必要范围 → 检查该动作/切点及被牵动的邻镜 → 导出新文件 → 附处理结果与待确认项。保留原片和失败，不用新文件悄悄覆盖正在审的版本。

交付 `review.md`：实际打开的帧与片段、是否完整播放、实际听音范围、技术检查、发现/修正、谁提供了辅助、用户是否认可。写未知或待验收是准确记录；不要为了打勾把文字自评写成实际观感。
