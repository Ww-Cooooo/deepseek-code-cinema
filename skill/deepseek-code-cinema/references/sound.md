# 声音是影片的一部分

先为这支影片做选择：需要观众听到什么，什么应留白，动作音落在哪里，旁白是否比屏幕文字更能帮助理解。默认考虑配乐和音效；不强制旁白，也不把低音铺底、提示音循环当成所有题材的答案。

## 先编排声音的结构

把音乐、环境、动作与留白写入镜头表。比如悬念的持续底声建立世界，一次动作音让变化落地，留白给观众理解，随后用新音色或旧主题的变化完成收束。图形电影可以克制而精确，实体场景需要考虑距离、空间和声源；不能只套统一低频或从头敲提示音。

声音和画面可以提前、同步或延后，须有叙事作用。冲击、上升、噪声、长尾、旋律和静音都是词汇，不是每片必备音色。先完成一段代表性声画小样；实际听音不能由波形或阅读乐谱代替。

## 落实可用音源

按任务选择：用户有权使用的音轨、许可明确且适用的免费素材、已有可用的本地配音，或适合这种风格的原创制作。记录文件、来源/作者、许可和必要署名；“网上找到”“AI 生成”不等于已确认再分发权。不要将流媒体加密文件当 WAV/MP3 使用，不绕过保护。

没有旁白而画面能独立讲明白时，可以用音乐与动作音组织节奏；知识负担太重时应减少屏幕文字、留足阅读，或落实可用旁白。没有任何音轨时不能直接删掉有声要求：在已有预算内制作合适原创声音，或明确缺项并只暂停最终有声验收。新付费配音/音乐服务超出普通本地制作授权时先取得对应许可。

起始工程 `scripts/sound.mjs` 是小型 PCM 合成器，读取 `score.json` 的事件（at、duration、frequency、gain、pan、voice），输出 WAV。支持 tone、pluck、noise；用于短提示音、轻质几何动画或程序配乐试作。它没有自动作曲或听感质量保证，不能把六秒示范音乐原样循环到每支片。可重写 score 与合成实现，也可使用完全不同、许可清楚的音源。

```text
npm run sound
```

事件时间使用秒；合成音轨总长从 `src/config.ts` 的总帧数与 fps 推导，不再手填一份片长。音画关键点从镜头时间推导或在镜头调整后同步修改。`film.audioFile` 指向 public 内音轨；生成失败或文件不存在时修复，不能设置 null 假装完成。用户明确要求静音时可以禁用并记录决定。

## 混音与真实检查

为旁白留空间，关键动作音不压过台词；让底乐有起伏与落点，长音在开头/结尾有包络，避免点击和突然截断。不要靠一直响来证明声音存在。听到掩蔽、尖刺、轰鸣、重复疲劳或声画错位时，回到对应时间局部改。

检查实际导出的 AAC/PCM 声道、时长、峰值和响度只是技术辅助。可以用 FFmpeg 的 volumedetect / loudnorm 输出观察异常，不把某个数值机械称为好听。建议保留峰值余量；内容和播放场景比统一响度数字更有意义。

实际完整播放并听音，至少关注首尾、叙事落点和声音密集处。无法听音的 Agent 应明确说“已检测音轨、尚无人听完”，交付影片给用户或可用的本地审片工具；静帧、波形、模型阅读 score 都不算听过声音。记录人工实际听过的范围，不能由用户未回复推断认可。
