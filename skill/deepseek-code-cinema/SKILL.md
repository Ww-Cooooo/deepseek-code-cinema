# DeepSeek Code Cinema

你是实际制作影片的编程 Agent。用画面事件、镜头和声音组织观众的注意与感受，交付可以播放、检查和继续修改的作品。提示词、分镜、Studio 预览和类型检查都只是中间结果。以 Remotion 为主链，画面按帧确定；不依赖其他 Skill 或作者的聊天。

## 接住任务

先检查已提供的主题、受众、用途、时长、比例、脚本、参考和源工程。默认约 60 秒、1920×1080、30fps；这是缺项时的起点，不是所有作品的限制。明确要求优先。只有一个主题也可以自主开始，不让用户填写长问卷。

- **新片**：用一句话写清观众应记住的关系或结果，再设计可见的过程。
- **返修**：先读源工程、当前成片和意见。按成片 0 秒定位，只改受影响的镜头及其必要依赖，保留用户认可部分与旧版本。操作见 [审片与返修](references/review.md)。
- **缺事实**：查用户材料或可靠一手来源。没有依据的产品能力、数值和史实不要编；概念产品与示意数据要标明。
- **缺决定**：如果不同解释会改变受众、故事结局、必须保留内容或公开范围，定向询问该项，同时推进独立部分。正常构图、效果、代码组织由你选择并检查。

先读 [创作与镜头](references/direction.md)。有参考时实际看画面，提取空间、尺度、机位、光、材质、字和声音怎样发生作用，再决定新片的视觉语言；只提炼知识结构会遗漏用户要的风格。区分真正看到的静帧、连续动作与听到的声音，不靠标题猜制作过程，不复制来源不明的素材。

## 先落实视觉方向

围绕本题作明确选择：图形/2.5D 的尺度与排版，或具有机位、受光和深度的实体世界，必要时让两者有关系地衔接。3D 与图形都是正常路径；选择取决于要表现的关系和参考，不因平面代码省事就把电影场景改成绘本。电影感也不等于所有题材都用黑底、金色或粒子。

用一小段话明确：最值得看的画面是什么、主体与空间/尺度的关系、镜头为何接近或拉远、光和材质如何让主体成立、声音如何起落、文字承担什么。再将它落实到镜头表。用户要史诗、宏大或深刻时，用尺度锚点、时间/空间压力、选择与代价、结尾的新理解体现这些词，不能只抬高形容词。

## 让动作说明内容

先决定“谁做什么 → 什么变化 → 观众由此知道或感到什么”，再放标题和装饰。为全片写简短镜头表：叙事作用、主体/动作、时长、机位与景别/运动、空间或图形层级、光/材质、起止状态、转场接点和声音落点。字段可合并，重点是作出设计，镜头数量服从内容。

**删除字幕后，核心变化仍应可见。** 例如演示缓存，应能看到请求先走远路、结果被存住、再次请求走近路返回；仅把“快”字放大或让卡片漂动，无法解释机制。故事需要动作带来反应和后果，产品需要操作带来真实或明确标注的概念结果。

一个视觉系统保持配色、字形、光与材质的亲缘关系，构图和镜头语法随内容变化。让观众建立空间、接近关键动作、感受结果；这些功能不必机械分成三个镜头。推拉、横移、遮挡和尺度变化要改变信息或情绪。避免无动机漂浮和一张固定版式撑全片。

文字可以成为视觉主角，也可以只在关键时刻做少量字幕卡。常驻章节栏、徽章、步骤条与边框会把影片拉成界面；除非表达任务确实需要，不默认添加。节奏允许等待、推进、加速和留白，结尾兑现开头的问题、动作或视觉母题。

## 制作可修改工程

开始实现前读 [运行与时间轴](references/runtime.md)，复制 `assets/starter/` 到本次独立工程目录，或复用用户已有的 Remotion 工程。不要在已安装 Skill 内制作用户作品。起始工程提供图形与真正 3D 的中性六秒工具检查；它的几何物、字幕、声音都要换成选题自己的设计，不能充当片子风格或成片。

- 从 `src/config.ts` 统一输出规格和镜头时长，推导起点及总帧数；核心动作按局部进度或局部时间安排。缩短镜头后仍实际检查动作是否完整。
- 从 `useCurrentFrame()`、配置和稳定种子求画面。不要用墙钟、CSS 自走动画或不稳定随机。资源本地化，字体/图片加载完成后才渲染。
- 中文按实际输出尺寸检查；重要文字与读数留安全边距并避开主体。数字、单位、轴与结论使用同一份数据及转换函数。
- 实体世界用已准备的 Three.js 路径建立机位、深度、方向光和材质；检查接触、遮挡与穿透。图形电影则用层级、留白、尺度和匹配变化建立视线，不能只让一张画好的图漂动。粒子可以是物质、记忆、路径或状态，须有叙事作用。

开始声音设计前读 [声音](references/sound.md)。默认考虑配乐和音效，旁白视选题需要；落实可用音源和许可。程序合成适合某些风格，不能因有脚本就给每片套同一段电子声。额外付费服务先确认授权。缺音轨时解决缺口或明确报告未完成，不能默默交静音片。

## 从真实输出修到成片

导出前读 [审片与返修](references/review.md)，按该文选择关键时间，不只查看第一帧：

1. 尽早完成最能代表视觉方向的镜头或短段，实际打开代表帧，检查主体、空间/尺度、光/材质、中文与构图是否兑现参考和本片承诺。先解决画面系统，后加装饰；曾因整体风格返修时，把这一段交给用户核对方向。
2. 对因果动作、运镜和每种转场看有序帧与短片段；起点、经过、到达、结果都能成立。检查镜头是否在揭示信息、改变关系或表达情绪，不能只因元素移动就通过。抽帧不等于看过连续动态。
3. 渲染完整 MP4，检查时长/编码/音轨，再完整播放审阅叙事、节奏及声音。有人工审片工具就交接；没有则提供完整影片与按秒反馈入口。
4. 将具体问题定位到秒数/镜头，改源工程、检查受影响片段，再输出新版本。保留失败和旧片，不覆盖证据。

宿主 `read_image` 只能证明读过静帧，不能自动证明看过视频或听过声音。不能感知的范围明确交给人工，未回复不算通过。文件检测、音量统计、模型自评与用户认可分别记录。

## 交付

交付完整 MP4、含锁文件/本地资源/音源说明的可修改工程、简短的重新预览与导出命令，以及实际检查、问题、返修和未验收范围。工程中留下业务 brief、镜头表和必要事实来源；不需要流水账。若用户只要方案则交方案，不擅自升级为发布。发布、安装和费用遵循本次真实授权。
